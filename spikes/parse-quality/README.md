# 解析质量体检（spike）

在写任何摄取代码之前，用**真实的**工业文档验证 [04 RAG 流水线](../../docs/04-rag-pipeline.md) 里的解析假设是否成立。

## 为什么要先做这件事

路线图把解析质量列为 R1，是全项目概率最高、影响最大的风险。原因是设计里有一条贯穿四层的依赖链：

```
PDF 能拿到可靠 bbox → chunks.bboxes 存得下 → 引用接口传得出 → 前端 pdf.js 画得准
```

这条链的起点如果不成立，要改的不是一处代码，而是 01（ADR-005）、02（chunks 表）、03（引用接口）、04（解析与分块）四份文档。这个体检只需要一两天，放到 M1 才发现则是几周的返工。

**用真实客户文档，不要用规整的公开 PDF。** 后者几乎必然全绿，得出的结论毫无意义。

## 安装

```bash
cd spikes/parse-quality
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

与主工程的依赖完全分离，spike 结束后整个目录可以删掉。

## 使用

```bash
# 体检一个目录下的所有 PDF
python check.py ~/samples

# 指定文件，并导出第 1、2、5 页的坐标可视化
python check.py 手册.pdf 规程.pdf --render 1,2,5

# 大文档快速试跑：只看前 20 页，跳过较慢的表格检测
python check.py ~/samples --max-pages 20 --no-tables
```

产出：控制台报告 + `out/report.json`（可归档，换参数后可与上一次 diff）+ `out/overlay/*.png`（坐标可视化）。

退出码 `0` 全部通过、`1` 有需关注项、`2` 有不通过项，便于将来接进 CI。

## 六项检查与它们对应的设计决策

| 探针 | 检查什么 | 不达标会推翻什么 |
| --- | --- | --- |
| 文本层 | 有多少页必须 OCR、有无解析失败的空白页 | OCR 占比高会大幅拉长摄取耗时，需重估 M1 工期与 `worker-parse` 规格 |
| 字符编码 | 拉丁字母是否被错误映射到汉字区、全角字符占比 | 04 文档 5.2：标准号入库时不是 ASCII，BM25 精确匹配整路失效 |
| 坐标 | bbox 是否合法、是否越界、页面尺寸是否一致 | **ADR-005**：坐标不可靠则引用溯源的整条链路需要重新设计 |
| 标题层级 | 有无 PDF 大纲；无大纲时启发式能识别出多少标题 | 04 文档 3.1：识别不出标题，结构感知分块退化为按长度硬切 |
| 表格 | 表格数量与规模、跨页表格、误检 | 04 文档 3.1 第 3 条：表格原子化与超长表格按行切分的可行性 |
| 页眉页脚 | 复现 2.3 节的剔除算法，看能否抓到、有无误伤正文 | 抓不到则页眉混进 chunk 污染检索；误伤则正文被静默丢弃 |

## 已经跑出来的结论

对 6 份 AQ 系列安全标准（化工 3 份、烟花爆竹 3 份）的实测结果，已据此回改了 04 与 06 文档：

- **半数是纯扫描件**，零文本层。OCR 从 M3 的边缘任务提升为 M1 必做项。
- **有文本层的 3 份全部存在字体错误映射**，`AQ/T 4127—2018` 提取出来是 `犃犙／犜４１２７—２０１８`，单份 117 处；全角字符占比 25%。因此 04 文档 2.3 新增了字符规范化步骤。
- **坐标质量完美**，1108 个 span 零非法零越界，ADR-005 成立。
- **固定带宽的页眉页脚算法不成立**：页眉底边在页高 10.4%，正文首行顶边在 11.0%，可用窗口只有 0.6%。已改为按 y 聚类取首尾行。

每条不通过或需关注的结论都会附带一句 `impact`，直接说明它影响哪份文档的哪个决策——这个脚本的目的是支持决策，不是产出一堆数字。

## 怎么看结果

**先看控制台的结论段。** 它会直接给出"可以进 M0"还是"先回改设计"的建议。

**再看坐标可视化。** 指标只能告诉你坐标合法，不能告诉你坐标正确。打开 `out/overlay/` 里的 PNG，红框是每个文本 span 的 bbox，蓝色虚线是页眉页脚判定带。红框应该严丝合缝地套在文字上；如果整体偏移或缩放不对，说明页面存在旋转或裁剪框偏移，前端高亮会跟着错位。这一步无法自动化，必须用眼睛看。

**最后看被判定为页眉页脚的内容。** 如果里面出现了长句或含实质信息的行，说明 8% / 60% 这组阈值不适合你的文档排版，需要在 `industry_profiles.parse_rules` 里为该行业单独配置。

## 结论怎么用

- **全绿**：解析假设成立，按现有设计进入 M0。
- **有 warn**：可以进 M0，但把这些项写成 M1 的验收用例，别让它们悄悄溜过去。
- **有 fail**：先回改对应的设计文档，不要带着已知的解析缺陷开工。典型的补救方向是引入版面分析模型（如 PP-StructureV2）替代启发式规则，这会改变 04 文档 2.1 的解析器矩阵和 M1 的工期估算。
